# 浏览器备份 · Browser Backup

一个只在本机运行的 Edge / Chromium 扩展：备份标签组与收藏夹、盘点已安装扩展、把扩展源码收进插件目录，并在插件里直接删除备份。

当前版本：**1.8.0**
插件目录：`Edge-browser-backup`

## 一、备份放哪：插件自己的文件夹

```
Edge-browser-backup/               ← 插件目录（含 manifest.json）
├── manifest.json                  ← 插件本体，备份不碰
├── app.html / app.js / app.css
├── ext.js / background.js / icons/
├── 备份扩展源码.command            ← 复制扩展源码的脚本
└── backups/                       ← 所有备份都在这
    ├── 扩展源码/<扩展名>-<ID前8位>/
    ├── 完整备份/edge-backup-日期时间.json     ← 标签组 + 收藏夹
    ├── .回收站/<时间>-<原名称>/    ← 删掉的备份先放这里，可恢复
    └── 位置.txt                   ← 脚本写入，记录插件目录的绝对路径
```

**换电脑只需拷走整个插件目录**，插件和全部备份一起走。

| 动作 | 去向 | 入口 |
|---|---|---|
| 备份 | 插件目录 `backups/` | 标签与收藏 →「备份到插件目录」；扩展 → 双击脚本 |
| 导出 | 浏览器默认下载文件夹 | 标签与收藏 →「导出 .json / 收藏夹 .html / 可读清单 .md」 |

## 二、安装

1. 把整个 `Edge-browser-backup` 文件夹放到一个**不会被移动、可写**的位置。
   （扩展加载后与路径绑定；放到只读目录会导致备份失败。）
2. 打开 Edge → `edge://extensions/` → 打开 **开发人员模式** → **加载解压缩的扩展** → 选中该文件夹。
3. 装好后自动弹出主界面；之后点工具栏图标打开。

> **改过文件夹名就要重新加载**：未打包扩展的 ID 由路径决定，移动或改名后旧条目会失效，需先移除旧条目再重新加载。改回同一个路径则会恢复原 ID。

权限：`tabs`、`tabGroups`、`bookmarks`、`storage`、`management`。全部用于本机读取，没有任何网络请求。

## 三、三个页签

```
标签与收藏   当前快照 / 备份到插件目录 / 导出 / 导入 / 恢复预览 / 进阶设置 / 执行记录
扩展         只读盘点：已安装扩展清单 + 导出 CSV
备份管理     备份位置（脚本 + 授权）/ 已有备份（两类）/ 删除 / 说明
```

页签切换会被记住。盘点、备份位置、备份列表各归各位，不再挤在同一页。

## 四、为什么扩展源码要用脚本复制

Edge / Chrome 的扩展目录位于浏览器配置目录内：

```
~/Library/Application Support/Microsoft Edge/Default/Extensions
```

浏览器按设计**禁止扩展通过 `showDirectoryPicker` 授权这一类路径**，点击选择时会提示：

> 无法打开此文件夹——由于此文件夹包含系统文件

这是浏览器的安全策略，扩展侧无法绕过，也没有替代 API（扩展读不到其他扩展的文件）。所以复制这一步交给插件目录里的 `备份扩展源码.command`，在浏览器外完成；复制结果落在 `backups/扩展源码/`，插件再从这里读取、展示、删除。

## 五、标签与收藏

进阶设置已从折叠面板改为常显卡片，三列等宽、带细分隔线，每组说明压到一行；导入区的拖拽框会随卡片高度自适应，底部不留空。

### 备份（写进插件目录）

点「备份到插件目录（.json）」，生成 `backups/完整备份/edge-backup-日期时间.json`，按钮下方显示当前备份位置。一份文件里同时包含标签组和收藏夹，不用分两次。

备份内容：标签组名称/颜色/折叠状态/成员顺序、标签网址与是否固定、收藏夹全部层级。

### 导出（下载到默认文件夹）

| 按钮 | 产出 | 用途 |
|---|---|---|
| 导出 .json | `edge-backup-日期.json` | 单独拿一份出去 |
| 收藏夹 .html | `edge-bookmarks-日期.html` | Edge / Chrome / Safari 都能直接导入 |
| 可读清单 .md | `edge-backup-日期.md` | 人眼核对，或手工重建分组时的对照表 |

### 导入（还原）

1. 点选或拖入 `.json` 备份。
2. **恢复预览**显示导出时间、窗口/组/标签/收藏数量、各组名称与颜色、标签构成、收藏夹根目录。
3. 选项：
   - **还原标签组**：在新窗口重建所有组与标签
   - **还原收藏夹**：*合并到原位置*（同网址跳过，可重复执行）或 *装进新文件夹*
4. 「移除文件」可清空当前载入的备份。

## 六、扩展页签（只读盘点）

列出名称、版本、类型（商店 / 本地 / 外部 / 策略）、启用状态、ID，本地解压扩展排在最前。

- **全选 / 单条勾选**：会被记住，已卸载的自动剔除。
- **导出清单**：有勾选时只导出勾选项，CSV 带 BOM。
- 本页只读，不向磁盘写任何东西。

每行带扩展图标（浏览器不提供时会回落到首字母色块），名称下方显示 ID；版本 / 类型 / 状态居中对齐，表头与单元格一致。

## 七、备份管理页签

### 1. 备份位置（两步）

| 步骤 | 做什么 | 说明 |
|---|---|---|
| ① 备份扩展源码 | 在 Finder 双击 `备份扩展源码.command` | 复制到 `backups/扩展源码/`，跑完点「刷新」 |
| ② 授权插件目录 | 点「授权插件目录」选含 `manifest.json` 的文件夹 | 列备份、删备份都需要；跑过脚本后会显示绝对路径 |

脚本会：跳过 `_metadata`、按 manifest 读名称与版本（`__MSG_*__` 会依次尝试 `default_locale` → `zh_CN` → `en` → 其他语言包）、清理同一扩展 ID 的旧副本、写入 `backups/位置.txt`。

### 2. 已有备份

- 列表**直接扫磁盘**，不依赖任何索引文件；脚本复制进来的备份同样会出现。
- **扩展源码 / 完整备份分成两组**，默认收起，点标题展开，展开状态会被记住。
- 每组最多显示 6 行，超出在组内上下滚动，不会把整页撑长。
- 扩展行显示对应扩展的图标（按文件夹名尾部的 ID 前 8 位匹配；未安装或取不到时回落到首字母色块）。
- 标题右侧显示 `N 个 · 体积`；扩展体积是**实测并缓存**（按 manifest 修改时间失效重算），不是估算，也不会把两类混在一起加总。
- 每行显示名称、版本、体积、文件数、时间、相对路径，以及「删除」——删除只是移入回收站。
- **清空扩展备份 / 清空完整备份**：按类型整体清理。
- 刷新时列表整块替换，不会先清空再重绘，所以不会闪抖。

### 3. 回收站

- 删除操作只把项目移动到 `backups/.回收站/`，每一项都带 `info.json` 记录原位置。
- 每项可「恢复」（放回原路径，重名会拒绝并提示）或「彻底删除」。
- 「清空回收站」一次性清空，这一步不可撤销。
- 浏览器沙箱到不了系统 Finder 回收站，所以回收站做在插件目录内。

### 4. 说明

- 商店扩展会随账号同步装回，备份是给「被下架、开发者弃坑」留后路。
- 本地解压扩展不在任何同步里，源码只在你那个文件夹。
- 备份出的商店扩展可用「加载解压缩的扩展」装回，ID 不变，数据仍能对上。
- 扩展配置（API key、规则、脚本）不随源码走，请用各自扩展的导出功能。

## 八、迁移到新电脑

1. 退出 Edge。
2. 整个拷走 `Edge-browser-backup` 文件夹（含 `backups/`）。
3. 新电脑放到固定位置 → `edge://extensions/` → 加载解压缩的扩展。
4. 打开插件 → 备份管理 → 授权插件目录 → 备份列表立刻可见。
5. 需要还原时，标签与收藏 → 导入 → 选 `backups/完整备份/` 里的 json。

## 九、记住了什么

| 项目 | 存放位置 | 失效条件 |
|---|---|---|
| 恢复预览的 4 个勾选 | `chrome.storage.local` | 不会失效 |
| 进阶设置 5 项 | `chrome.storage.local` | 不会失效 |
| 扩展列表的勾选 | `chrome.storage.local` | 扩展被卸载时剔除该条 |
| 当前停留的页签 | `chrome.storage.local` | 不会失效 |
| 插件目录句柄 | IndexedDB | 重启后可能降级为待授权，点「恢复授权」即可 |
| 上次备份时间 | `chrome.storage.local` | 不会失效 |

> 从 1.7.1 及更早升级：备份文件夹由 `backups/标签组备份/` 改名为 `backups/完整备份/`，把旧文件夹改名即可，文件名不影响读取。
> 从 1.5.0 升级：取消「备份索引.json」与「直接备份（目录副本）」流程，备份管理独立成页；磁盘上已有的备份文件夹照常识别，无需迁移。
> 从 1.4.0 升级：目录名改为 `Edge-browser-backup`，需重新加载扩展并重新授权一次插件目录。

## 十、进阶设置

| 分组 | 选项 | 默认 | 说明 |
|---|---|---|---|
| 导出范围 | 包含未分组的零散标签页 | 开 | 关闭后只备份组内标签 |
| 导出范围 | 排除 edge:// 等内部页面 | 开 | 内部页面无法被扩展重开 |
| 还原行为 | 还原组颜色与折叠状态 | 开 | 关闭则统一灰色、不折叠 |
| 还原行为 | 还原后让标签休眠 | 关 | 标签变灰点，点击才加载 |
| 备份提醒 | 超过 N 天未备份时高亮 | 7 天 | 只影响右上角胶囊颜色 |

## 十一、已知限制

- **Edge 配置目录无法被扩展授权**（含 `Extensions`），源码备份必须走脚本；这是浏览器限制，不是权限没给。
- **`edge://` 内部页面无法重建**，还原时自动跳过并计数。
- 标签组只在同一窗口内连续成员才能还原为一组。
- 固定标签不允许进入标签组，还原后不属任何组。
- 标签页是重新打开，不恢复滚动位置/表单内容。
- **插件目录必须可写**；放在只读位置会备份失败。
- 打包 .crx 时 `backups/` 会被一起打进去，需要干净包就先移走。
- 复制时跳过 `_metadata`；重新备份会先删同名文件夹再复制，不留旧版本残留。
- **彻底删除与清空回收站不可撤销**；普通「删除」只是移入 `backups/.回收站/`，可恢复。
- 不联网、不上传数据。

## 十二、文件结构

```
Edge-browser-backup/
├── manifest.json           MV3 清单（tabs / tabGroups / bookmarks / storage / management）
├── background.js           点击图标打开主界面
├── app.html                主界面（三个页签）
├── app.css                 样式（跟随系统明暗主题）
├── app.js                  标签与收藏：采集 / 备份 / 导出 / 还原 / 设置记忆
├── ext.js                  扩展盘点 / 备份位置 / 扫描 / 删除
├── 备份扩展源码.command     浏览器外复制扩展源码 + 写位置.txt
├── backups/                运行时生成：全部备份
└── icons/
```

## 十三、备份文件格式（v1）

```json
{
  "schema": "edge-tabgroup-backup",
  "version": 1,
  "exportedAt": "2026-11-06T07:20:00.000Z",
  "browser": "Edge 156",
  "stats": { "windows": 1, "groups": 3, "tabs": 24, "bookmarkItems": 186 },
  "windows": [
    {
      "focused": true,
      "groups": [{ "key": "g12", "title": "项目 A", "color": "blue", "collapsed": false }],
      "tabs": [
        { "url": "https://example.com", "title": "示例", "pinned": false, "group": "g12" }
      ]
    }
  ],
  "bookmarks": [
    { "id": "1", "title": "收藏夹栏", "children": [
      { "title": "开发", "children": [
        { "title": "MDN", "url": "https://developer.mozilla.org/" }
      ]}
    ]}
  ]
}
```

`group` 为 `null` 表示未分组；`groups[].key` 与 `tabs[].group` 对应。
